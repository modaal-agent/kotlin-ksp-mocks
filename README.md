# kotlin-ksp-mocks

Build-time recording-spy mocks for Kotlin interfaces, generated by a
[KSP](https://kotlinlang.org/docs/ksp-overview.html) processor into the test
compilation only. Nothing is committed, no annotation artifact touches the
main classpath, and the generated member vocabulary matches
[swift-sourcery-templates](https://github.com/modaal-agent/swift-sourcery-templates) —
one mock dialect for a codebase that tests the same logic on both platforms.

## Wiring

```kotlin
// build.gradle.kts of the module whose tests need mocks
plugins {
  alias(libs.plugins.ksp)
}

dependencies {
  kspTest("dev.modaal:mocks-processor:<version>")   // kspJvmTest in a multiplatform module
}

ksp {
  arg("kspMocksTargets", "com.example.FeedEnvironment,com.example.FeedDependency")
}
```

`kspMocksTargets` is a comma-separated list of fully-qualified interface
names. Selection is a build-script list rather than an in-source marker by
measurement: an interface declared in `main`/`commonMain` reaches the test
compilation's KSP pass as a compiled binary, so no comment or KDoc marker
survives to be read there — and putting an annotation on the main classpath
is exactly what this processor exists to avoid.

Generation lands under `build/generated/ksp/…` during test compilation and is
never committed: there is no drift to check, and an interface member added in
`main` fails the next test compile against the regenerated mock.

## Generated API

For an interface method, the mock records and seeds with three members:

```kotlin
interface FeedEnvironment {
  suspend fun load(id: String): FeedPage
}

val environment = FeedEnvironmentMock()
environment.loadHandler = { id -> FeedPage(id) }   // the only seeding mechanism
environment.load("p1")
environment.loadCallCount   // 1
environment.loadArgs        // ["p1"]
```

- `<fn>CallCount` — calls made, counted before the handler runs.
- `<fn>Args` — recorded arguments: one recordable parameter is stored
  directly, several become a nested `<Fn>Args` data class, function-typed
  parameters stay out of the record (storing a closure would pin the
  caller's captures to the mock's lifetime).
- `<fn>Handler` — nullable lambda, the only seeding mechanism. When unset:
  `Unit` returns nothing, a nullable return yields `null`, a guessable
  default (`0`, `""`, `emptyList()`, …) is returned, a `Flow` return replays
  the mock's `<fn>Channel`, and anything else fails with
  `"<fn>Handler expected to be set."`.

Streams are `Channel`-backed — push, then close to end the stream:

```kotlin
environment.eventsChannel.trySend(FeedEvent.Tick)
environment.eventsChannel.close()
```

Properties: a mutable requirement is stored and counts writes in
`<prop>SetCount`; a read-only `Flow` property gets `<prop>GetCount` +
`<prop>GetHandler` + the channel fallback; a read-only requirement with a
guessable default is a re-seedable stored `var`; anything else becomes a
constructor parameter — a pure-property interface generates a
constructor-seeded bag, so a member added to it breaks consumers at compile
time instead of at run time.

## Not supported

Generic interfaces and `vararg` parameters fail generation with an explicit
error. Interfaces only — the processor does not mock classes.

## Releases

Published to a static Maven host as `dev.modaal:mocks-processor`; the version
is derived from the release tag by the publish workflow. The `:receipt`
module in this repository is the end-to-end proof: its tests consume mocks
generated during the build's own test compilation.
